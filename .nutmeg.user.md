# Nutmeg profile

Advanced engineer, new to football data specifically. Python (pandas) on the
backend, TypeScript on the front end. Building a product: **EnchantmentBet**, a
football and basketball prediction app — FastAPI + MongoDB backend, Next.js
frontend, with a Dixon-Coles Poisson / pace-efficiency / Elo ensemble and a
Claude review layer.

Because the football-data experience is new but the engineering is not: explain
the *domain* concepts (xG, PPDA, coordinate systems, possession-adjustment)
rather than the code, and don't soften the statistical caveats.

## Warnings that apply to this profile

**Scraped sources (FBref).** Scrapers break whenever the site changes its
markup. Respect the rate limit — roughly 10 requests/minute — and cache
aggressively. This project already has the pattern to copy: the
`team_stats` MongoDB collection in `backend/app/providers/stats_cache.py`
persists fetched data across restarts so a rate limit is paid once, not
repeatedly.

**New to football data.** Start with StatsBomb open data — it is free,
event-level and includes xG. Do not trust any xG model blindly; different
providers' models disagree materially on the same shot. Draw no conclusions
from fewer than ~10 matches or ~900 minutes; below that you are reading noise.
This matters directly here — the app's current ratings come from a completed
2024/25 season because of free-tier limits, which is a sample caveat worth
stating wherever predictions are shown.

**Key-based APIs (api-sports.io, Football-data.org).** Understand the tier
limits: api-sports free is 100 requests/day *and* 10/minute, which already
shapes this codebase's whole fetch strategy. Redistribution of provider data is
usually prohibited by the terms. API keys are secrets and must never be
committed to git.

> **Live issue:** `backend/.env.example` is tracked by git and contains three
> real keys (`APISPORTS_KEY`, `APITENNIS_KEY`, `NEWSAPI_KEY`). They are in
> committed history as of `e16ea1f`. Rotate them and replace the values with
> empty placeholders before this repo goes anywhere public.

**Building a product.** Commercial use of football data usually requires a
separate licensing agreement — free and open tiers are typically
non-commercial. Confirm the terms for api-sports.io and any provider added
later before charging users or running ads.
